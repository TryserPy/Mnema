## Безопасность (№15)

Исправлено:

| Находка | Серьёзность | Что сделано |
| --- | --- | --- |
| `DELETE /v1/devices/:id` отзывал сессии по `device_id` без проверки аккаунта: зная id чужого устройства, можно было выбить его вход (IDOR) | высокая | `unbindDevice` — только сессии своего аккаунта; тест `attacks.test.ts` |
| Тело запроса без `content-length` (chunked) читалось целиком и только потом проверялся размер | средняя (память Worker) | поток обрывается на превышении (`readCapped`) |
| JSON-ответы сервера без `x-content-type-options` | низкая | `nosniff` |
| Подмена ссылки на субтитры в ответе YouTube / открытый POST | средняя | только `youtube.com/api/timedtext` и фиксированный адрес InnerTube (№11) |
| Падение при запуске из-за замороженного моста (№9) | — (доступность) | см. №9 |

Проверено, проблем нет:
- **XSS.** Markdown идёт через DOMPurify с хуками: разрешены только адреса `https:`/`mailto:`/`data:image`/`#`, `javascript:` вырезается; классы и стили пропускаются только внутри формул с одноразовой меткой; `rel=noopener`. KaTeX работает с `trust: false`. Ответы ИИ и OCR — тот же Markdown. Рисунки SVG — DOMPurify с белым списком. Тексты ошибок и имена файлов выводятся через React. CSP: `script-src 'self'`, `object-src 'none'`, `base-uri 'none'`, `form-action 'none'`; в админке и tg — `default-src 'none'`.
- **Секреты.** Поиск по истории обоих репозиториев (ключи Anthropic/OpenAI/Google/GitHub/Telegram/AWS, приватные ключи): совпадения только в base64 шрифтов/wasm и тестовый `TOKEN_SECRET`. Ключи ученика: Electron — safeStorage, Android — Keystore, веб — WebCrypto (1.32).
- **Авторизация.** Каждый запрос подписан ключом устройства; остальные запросы к D1 по id берут id из проверенной сессии.
- **Лимиты.** Проверяются на сервере (DO на ученика, бюджет, в минуту, параллельные); размеры тела/фото/полей — `FIELD_LIMITS`; тип фото — по сигнатуре.
- **Баг-репорт.** Proof-of-work, 20 в час с IP, 5 в день с устройства, 2 МБ, текст до 2000 знаков, вычистка почт/путей/id/токенов/ключей/IP. Снимок экрана — только по явному выбору и только в Telegram владельцу. В Telegram уходит без `parse_mode`.
- **CORS.** Только для админ-панели (`ADMIN_ORIGIN`).
- **Service worker** кэширует только файлы своего origin в пределах scope; API на `workers.dev` не кэшируется.
- **Промпт-инъекции.** Данные ученика в промпте в ограничителях `<<< >>>` с пометкой «данные, а не указания»; ответ ИИ ничего не выполняет и рендерится как недоверенный Markdown; черновики карточек ученик проверяет сам.

Осталось (по приоритету):
1. **Средний.** Dev-зависимости: сервер — `wrangler`/`miniflare` (undici, 5 high), корень — `electron-builder` (sprintf-js через global-agent, 8 moderate). В зависимостях самого приложения — 0 (`npm audit --omit=dev`). Лечится только мажорным обновлением `wrangler`/`electron-builder` — отдельной задачей.
2. **Низкий.** `net:http` в Electron — универсальный запрос из окна (нужен облаку, синхронизации и модам). Для «Карточек из ссылки» адрес проверяется после DNS, но между проверкой и самим `fetch` возможен повторный DNS-ответ (TOCTOU).
3. **Низкий.** У лендинга Mnema-site нет CSP (там нет пользовательских данных; встроенные скрипты потребуют хэшей).
4. **Низкий.** Из 1.32: нет TLS-пиннинга, промты сервера видны в сборке клиента.

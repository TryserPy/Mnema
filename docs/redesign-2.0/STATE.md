## Главные выводы (согласованы между агентами; проверено по коду/замерам, кроме помеченного)
1. **Умный план = автопилот = подготовка к контрольной — один механизм.** Уже есть `buildQueue` (`srs.ts:355`). На «Сегодня» шесть
   кнопок запуска → одна «Учиться» (≈N мин · k шагов) + «почему такой порядок» + «пропустить шаг». «Начать план» отдельно не нужна.
2. **Единая «слабость»** (сейчас 4–6 разных определений) → `weakness.ts` на полях FSRS; «Выучено» ≠ «Готовность к дате» ≠ «Слабые места».
   «Выучено 43 %» сейчас = доля существующих карточек, а не доля темы (`srs.ts:484–497`) — нужен охват отдельно. Тип ошибки в данных не существует.
3. **«Исправить»/«Повторить ошибки» идёт в cram и не пишет в FSRS** (`Review.tsx:139–146`) — петля не замыкается; нужен режим `ahead`.
4. **Контрольная — сущность**: дата + несколько тем (сейчас только `Topic.examDate`). Режимов ОГЭ/ЕГЭ/студентов не нужно.
5. **Баг 1** (меню «Ещё» за экраном): три слоя спорят — CSS разной специфичности (`design.css:212` vs `styles.css:965/1039`), JS `fitInView`
   (`ui.tsx:826–851`, дыра: условие `r.top < vh-120`), нет flip-вверх и пересчёта при resize. План: чистый `menuPlace.ts` + шторка снизу на телефоне.
6. **Баг 2** (квадратик): `rootMargin:-72px` в `NoteEditor.tsx:370` — нужен только полноэкранному режиму, root=окно. Новое условие: ВСЯ панель выше
   видимого верха прокручиваемой области (+ липкая полоса в полноэкранном), гистерезис 8–12 px.
7. **Баг 3**: по коду «итоги недели», «16 недель» (это история), «прогноз 14 дней» от периода НЕ зависят; зависят KPI и «Слабые темы». Проблема в раскладке
   (переключатель над всем). Но найдены настоящие логические ошибки: «Слабые темы» показывают темы с 88–90 % (нет порога); порог выборки разный (1 vs 5).
8. **Баг 4** (граф): рисуется на canvas, но физика d3-force считается на главном потоке по шагу за кадр. Замер (Node, без отрисовки): шаг при 100/500/2000 темах
   с терминами 3,2 / 22,8 / 131 мс; без терминов 0,6 / 3,4 / 19,5 мс. Термины включены по умолчанию (×5 узлов). Лечится уровнями детализации
   (предметы → темы по клику, термины скрыты, «фокус + окружение», замороженная/кэшированная раскладка), а не «графом со всем».
   **Не измерено:** FPS отрисовки в браузере и на телефоне.
9. **Скрытые лаги вне графа** (замер, 500 тем / 10 000 карточек): `SubjectScreen` считает `todayCounts` на каждую тему — 675 мс; 2000 тем — 8,8 с;
   сохранение всего AppData = 11 МБ JSON, 79 мс на сохранение; «Сад» 93 мс.
10. **Сад и Достижения — убрать** (единодушно: нет учебной ценности, не масштабируются, награды за ритуалы). «Серия дней» сейчас видна без переключателя
    (`Today.tsx:95`) — нарушает правило автора. Вопрос Q5.
11. **Данные (риски, найдено Architecture, часть подтверждена тестом агента):** `normalizeData` — белый список полей (новое поле теряется), `mergeData` берёт `...local`,
    слияние тем целиком по `updatedAt` **уже сегодня теряет правку конспекта** (ПК правит текст, телефон позже ставит ★ — выигрывает телефон) — починить `noteAt` + снимок перед sync.
    NoteEditor при закрытии может переписать конспект просто при открытии.
12. **История конспекта** — только локально, снимки на границах правки, ≤25 на тему, ~3 МБ, сжатие; не в облако/Wi-Fi. **Корзина** — контейнер `trash` через единую точку в `commit()`,
    восстановление = `restoreRemoved`. «Вернуть» там, где его нет; экран автокопий. Ленту версий в AppData — не делать.
13. **Формулы/моды:** убрать справочные вкладки «Формулы» и «Моды»; код-плагины (исполняют чужой JS) — убрать после подтверждения; стили (CSS-моды) мигрировать в «Оформление».
    **Саму поддержку формул (KaTeX, список «Формулы», старые конспекты, импорт Anki/Obsidian) убирать НЕЛЬЗЯ.** Вопрос к автору (Q1–Q2).
14. **ИИ:** почти всё делается без ИИ (разбор ошибки по дистракторам теста, похожий вопрос, «сопоставить», «по порядку», конспект→набор правилами `important.ts`).
    ИИ только по запросу и если настроен; иначе кнопок нет. При выделении видно 2 действия («Объяснить», «Вопрос по тексту»), остальное чипами. Склеить 5 входов «карточки из конспекта» в один `BulkCards`.
    Дефекты: кнопки ИИ видны без ключа/сети; ответ ИИ попадает в `card.why` без пометки.
15. **Типы заданий:** только «сопоставить» и «по порядку» (из списков/дат), без записи в FSRS; «найти ошибку» отложить; «верно/неверно» не делать.
16. **Стихи:** оставить (PoemView), влить в общую очередь, добавить дедлайн «к дате». Предложения «Стихи v2» — гипотезы, не «доказано» (Learning Science §5).

    «что я делал» → Профиль → «Мой прогресс». «Возможности»: 21 → 13 переключателей.

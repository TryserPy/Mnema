## Что хочет автор (ученик, пишет голосом, любит идеи от Claude)
Принципы: простота интерфейса ≠ мало функций; главное видно сразу, продвинутое — глубже и только когда нужно. Не копить функции ради функций. Не расширять аудиторию искусственно. Выключенная функция нигде не видна. На телефоне — никаких подсказок про клавиши и мышь.

### Баги
1. Меню «Ещё» в конспекте частично выходит за экран (проверить причину, разные размеры окна и положения меню).
2. Кнопка-«квадратик» с инструментами (выделение/добавление/вставка) в редакторе конспекта появляется слишком рано: часть верхних кнопок ещё видна. Должна появляться, только когда верхняя панель действительно стала недоступна.
3. На главном экране переключатель «неделя / месяц / всё время» зависит блоки «итоги прошлой недели», «прогноз на 2 недели», «прогноз на 16 недель» — они НЕ должны зависеть от периода. Разделить блоки, зависящие от периода, и независимые аналитические. «Слабые темы» могут иметь свою логику. Исправлять логику зависимости, а не вид.
4. Граф знаний сильно лагает при большом числе тем. Найти реальную причину (не «оптимизировать»): lazy loading, фильтрация, ограничение глубины, кластеризация, виртуализация, подграфы, уровни детализации, альтернативная визуализация.
5. «Сад» не имеет функционального смысла и не масштабируется (несколько классов, много предметов). Варианты: A) убрать; B) радикально переосмыслить, чтобы масштабировался и был полезен.
6. Достижения: есть ли учебная ценность? Нужны / заменить / спрятать / убрать.

### Структура
Идея: Учусь → Знания → Профиль. Учусь: умный план, повторение, домашка, контрольные, тесты, автопилот. Знания: конспекты, карточки, темы, термины, карты, статистика. Профиль: настройки, история, параметры, доп. возможности. Не окончательно — нужен UX-анализ и предложения.

### Новые функции (проанализировать каждую: проблема, решение, ценность, сложность, зависимости, риски)
- Умный план на сегодня: анализирует контрольные, домашку, карточки, повторения, слабые темы; сам строит порядок; кнопка «Начать план»; идёт по шагам; это не To-Do.
- Подготовка к контрольной: предмет, тема, дата → анализ темы, что уже изучено, слабые места, план до даты, распределение повторений, конкретные задания. Пример: «Алгебра → квадратные уравнения — 43%, требуется повторение», кнопка «Исправить» → подборка проблемных карточек. Слабое место = не только % верных, но и давность, число попыток, стабильность, сложность, тип ошибок.
- Конспект → учебный набор одной кнопкой (карточки, термины, даты, формулы, вопросы, определения, задания). ПЕРЕИСПОЛЬЗОВАТЬ существующую инфраструктуру (есть «Сделать из конспекта», src/noteTools.ts, src/important.ts, src/ai.ts, src/testgen.ts, src/changes.ts и т. п.), а не строить параллельную.
- Одна тема → разные типы заданий (выбрать, вписать, сопоставить, расставить по порядку, найти ошибку, решить пример, объяснить своими словами…). Не набор случайных мини-игр: у каждого типа понятная учебная функция.
- Объяснение ошибок: «Неверно. Почему?» → краткое объяснение именно этой ошибки → похожий вопрос → «Объяснить проще».
- AI внутри конспекта при выделении: объяснить проще / как для 5 класса / пример / вопрос по тексту / другое полезное. Что видно сразу, что в доп. меню.
- Глобальная кнопка «+» из любого места: конспект, карточка, домашка, термин, тема, быстрый вопрос и т. п.
- История изменений конспекта (версии + восстановление) и Корзина (удалённое не исчезает сразу).
- Учебный автопилот: на главном экране одна кнопка «Учиться»; приложение само решает (напр. 10 мин слабая тема, 5 мин карточки, 10 мин к контрольной, 5 мин работа над ошибками).
- Граф знаний: связи между предметами, темами, подтемами, терминами, карточками, конспектами, контрольными, уровнем знаний. Нельзя просто «сделать больше» — нужна масштабируемая модель отображения.
- Справка: формулы УБРАТЬ из приложения, моды УБРАТЬ из приложения; документацию перенести на сайт; в приложении только необходимая помощь.
- «Как учиться»: переработать полностью — просто, практично, на доказательных методах, с реальными интерактивными примерами (пользователь пробует метод). Исследовать: active recall, retrieval practice, spaced repetition, interleaving, feedback и др. с хорошей доказательной базой.
- Обучение стихотворениям: отдельная система (воспроизведение по памяти, интервальное повторение, постепенное уменьшение подсказок, части, проверка последовательности, повтор проблемных фрагментов). Проверить научные основания, не выдавать популярные советы за доказанные факты.
- ОГЭ / ЕГЭ / студенты: ценность для обычного школьника, для ОГЭ, для ЕГЭ, для студента. Не расширять аудиторию искусственно; понять реальную позицию продукта.

## Общие принципы автора
Главное очевидно (пользователь понимает, что делать дальше). Меньше визуального шума — можно менять доступность, не удаляя функции. Advanced ≠ visible. Обучение важнее геймификации (никаких механик ради engagement). AI решает проблему, а не «ради AI». Не дублировать существующую инфраструктуру — сначала переиспользовать. Масштабируемость (много предметов, тем, карточек, конспектов, связей). Простота важнее количества функций. Не бояться критиковать уже сделанное и удалять неудачные концепции: «оно уже есть» — не аргумент.

## 0. Главное за минуту

1. **Ядро у Мнемы маленькое и сильное** (конспект → карточки → FSRS → «Начать» + контрольная + домашка). Вокруг него выросло ~2–3 раза больше «периферии» (темы оформления, моды, сад, достижения, карта, 3 способа синхронизации/обмена, 2 вида ИИ). Последние два выпуска (1.7, 1.8) почти целиком ушли в периферию: файл изменений для нейросети (~1600 строк: `changes.ts` 827 + `mnemaText.ts` 429 + `ChangesDialog.tsx` 351), фон/значки/темы. Ядро (планирование, слабые места, контрольные) не двигалось.
2. **Реальная проблема главного экрана — не «мало кнопок», а много перекрывающихся.** На «Сегодня» при 144 карточках: «Начать (144)», «Подготовиться к завтра · 51», «Готовиться · 2», «Готовиться · 3», «Учить · 5», «Учить · 4» — это пересекающиеся подмножества одного и того же. Ученик должен сам решить, что из них важнее. Это и есть задача «умного плана» **[проверено, скрин `d-40-today-loaded.png`]**.
3. **«Автопилот», «умный план» и «подготовка к контрольной» — один механизм, не три.** Автопилот в зачатке уже есть: `buildQueue` (`srs.ts:355`) сам кладёт «в обучении» → «к контрольной» → «завтрашние предметы» → остальное с перемешиванием тем. Не хватает трёх вещей: **бюджета времени** («у меня 10 минут»), **единой метрики слабости** и **контрольной как сущности** (сейчас это поле `Topic.examDate` — одна тема, а контрольные бывают по 3–4 темам).
4. **Убирать до того, как добавлять.** Сад, Достижения (как экран), моды-программы, «Стили» (CSS-моды), справка «Формулы», 3 из 4 виджетов, 3 из 4 входов «карточки из конспекта» — это ~3500 строк и 4–5 разделов настроек, которые не дают учебной пользы, но множат матрицу проверок (стиль × 15 тем × плотность × углы × шрифт).
5. **Чего реально не хватает** (не из списка автора): бюджет времени и «разгребание долга» после пропуска; запись результата контрольной (оценки) — единственная честная проверка девиза «запомнить больше за меньшее время»; «вставить текст параграфа → набор» без ИИ (холодный старт); картинки с закрытыми частями (карты, схемы); «когда тебе удобно учиться» при первом запуске.

## 1. Что такое Мнема

**Одна фраза:** «Мнема делает из твоего конспекта карточки и сама подсказывает, что повторить сегодня, чтобы к контрольной ты помнил, а не зубрил ночью».

**Три главных сценария ценности**
1. **«10 минут в день»** — открыл → «Начать» → закрыл. Повторения раз в день по расписанию вместо зубрёжки. (Ядро; удержание.)
2. **«К контрольной»** — поставил дату → видно, насколько готов, что слабое, что делать сегодня. (Самая острая потребность школьника; сейчас сделана наполовину.)
3. **«Из параграфа в карточки за пару минут»** — конспект/фото/вставленный текст → набор → учить. (Холодный старт; сейчас это 9–10 действий на 3 экранах **[оценка]**.)

Сильный четвёртый, но «узкий по предметам»: **наизусть** (стихи, слова, даты, термины) — для литературы 5–9 классов это массовая задача, а не ниша.

**Кто пользуется** (все — **[предположение]**, телеметрии нет):
| Аудитория | Что берёт |
|---|---|
| Обычный школьник 5–9 кл. | Сегодня, карточки, домашка, стихи, словари, виджет |
| ОГЭ (9 кл.) | то же + даты контрольных; горизонт месяцы |
| ЕГЭ (11 кл.) | то же, объём 1000+ карточек; покрывает «запоминание», не «решение вариантов» |
| Студент | работает, но это не целевая аудитория (см. п. 7) |
| Автор/продвинутые | Obsidian, Anki, ИИ-ключ, файл изменений, моды, темы |

Главное противоречие: интерфейс говорит «ребёнку», а в «Данных» и «Возможностях» лежат инструменты для разработчика (WebDAV, Obsidian, API-ключи ИИ, JS-моды, CSS).

## 4. Дубли и feature creep

**A. «Что учить сейчас» — семь способов запустить повторение:** «Начать», «Фокус», «Подготовиться к завтра», «Разминка», «Готовиться · N» (контрольная), «Учить · N» (★-тема), «Учить» в теме/предмете/словаре. Один механизм (очередь) — семь входов с разными правилами. → один планировщик.

**B. Карточки из конспекта — 5 входов, 4 из них одно окно:** выделение → «В карточку» (оставить); панель «Важное» → «В карточку» по одному; «Важное» → «Сделать карточки из всего»; «⋯» темы → «Карточки из конспекта»; вкладка «Карточки» → кнопка «Карточки из конспекта» (×2). Три последних — один и тот же `BulkCards` (`ImportantPanel.tsx`, `NoteToCards`). → одна кнопка «Сделать набор» (п. 6).

**C. Слабые места — разбросаны по 6 местам:** «Слабые темы» (Stats), трудные карточки (leech), `ExamPlan.weak` (`srs.ts:~600`), советы «ошибки с уверенностью», `warmupCards`, статус темы `topicStatus`. Шесть определений «слабого». → одна функция (п. 6, «Слабые места»).

**D. Тест/проверка — четыре формата:** пробная контрольная, «Проверь себя до чтения», «Закрой и перескажи», повторение. Различия в содержании, не в механизме.

**E. ИИ — три несвязанных пути:**
1) ИИ в приложении по ключу пользователя (`ai.ts`: «Объясни иначе», формулы, фото) — охват узкий: ключ API у школьника **[предположение]**, выключено по умолчанию, на сайте-браузере вообще нет (`aiAvailable` требует `mnemaApi.aiAsk`);
2) «Файл изменений» — без ключа, через любой чат, но вручную (копируй/вставь);
3) мод «ИИ-вопросы» (`plugins/catalog.ts:218`).
Брифовые «ИИ в конспекте» и «объяснение ошибок» станут четвёртым и пятым применением пути 1. Прежде чем их строить, нужно решить стратегию: см. п. 6, строки 6 и 5.

## 5. Отдельные оценки

### 5.1 «Сад знаний» — **удалить** (вариант A)
- Что делает: тема → растение, стадия = доля выученных карточек (`Garden.tsx:30-33`), «вянет» по просрочке, «полить» = запустить повторение, «погладить» = анимация сердечек.
- Уникальной информации нет: то же самое уже показано полосой прогресса темы и значком «к повторению» в списке тем (`SubjectScreen`, скрин `d-20-subject.png`) и в левой панели.
- Не масштабируется: на моих тестовых данных — 66 растений в длинной ленте (`d-13-garden.png`); у реального ученика с 12 предметами по 20 тем — 240. Фильтр по предмету не решает: смысл «сада» — видеть всё сразу.
- «Погладить» — игрушка; принцип автора «никаких механик ради engagement».
- Цена: 380 строк + SVG-арт + анимации + пункт «Возможностей» + вкладка + пункт палитры.
- Что сохранить: одну идею — «что давно не повторял, увядает» → это уже `topicStatus` + число «к повторению». Ничего переносить не нужно.
- Данных в `AppData` сад не хранит (стадии считаются) → удаление безопасно для совместимости **[проверено: нет полей]**. Флаг `features.garden` оставить в типе как неиспользуемый.
- Вариант B (переосмысление) не рекомендую: любое осмысленное переосмысление (heatmap «предмет × давность») — это уже не сад.

### 5.2 «Достижения» — **убрать экран; серию оставить тихим числом**
- Состав (`progress.ts:94-125`): 5 по серии дней, 2 по числу ответов, 1 «Надёжная память» (50 карточек > 3 недель — единственная с учебным смыслом), 1 «Конспектист» (5 конспектов > 200 знаков — награда за объём текста), 1 «Словарь 50 строк», 1 «3 пробные контрольные» (слабый толчок к самопроверке), 1 «Ранняя пташка».
- Учебной ценности почти нет: награды за *присутствие* и *объём*, а не за запоминание. Серии мотивируют ходить, но риски известны: минимальные «кормящие» сессии из одной карточки, тревога при срыве **[оценка; не проверял на данных учеников]**.
- Всплывашка о новом значке (`App.tsx:129-136`) — прерывание ради награды.
- Что оставить: серия как маленькое число (а не как «значок»), под переключателем; «Выучено надолго: N» — уже в «Цифрах» (KPI «Выучено»).
- Цена удаления мала: `progress.ts` (часть), блок `Awards` в `Stats.tsx`, `settings.awardsSeen`, пункт «Возможностей».

### 5.3 «Карта знаний» — **переосмыслить: убрать глобальный граф, дать «связи» внутри темы и тепловую карту предметов**
- Что показывает (`KnowledgeMap.tsx:35-72`): предмет → тема (это уже дерево слева), тема → жирные термины, общие термины между темами (единственная нетривиальная информация), цвет = готовность.
- На 66 темах граф нечитаем (`d-14-map.png`: подписи накладываются) — это не только лаги, а **модель отображения**. «Больше узлов» (карточки, конспекты, контрольные, термины) сделает хуже: узлов будет тысячи.
- Что действительно полезно ученику: (1) «что с чем связано» — **внутри темы**: «Эта тема связана с: …» по общим терминам и ссылкам `mnema://`; (2) «где слабо» — это тепловая карта предмета (тема × готовность) или просто отсортированный список слабых тем.
- Предложение: граф ≤ ~40 узлов (один предмет, иерархия предмет→тема→подтема, цвет=готовность), без терминов по умолчанию; «связи» — панель в теме. Остальное (глобальный граф) — удалить или оставить для «Для продвинутых».
- Класс сейчас: НИШЕВАЯ (выкл. по умолчанию).

### 5.4 Моды/плагины — **удалить целиком**
- Две отдельные вещи под одним словом: **«Стили»** (9 готовых CSS + свой CSS + `.mnemamod`) и **«Моды»** (JS-программы с доступом ко всем данным, `app.http`, `app.ai`).
- Объём: `PluginsSettings` 306 + `ModsSettings` 207 + `plugins/host` 297 + `catalog` 253 + `PluginScreen` 41 + `mods.ts` 109 + `bus.ts` 19 + `ModsHelp` в `Help.tsx` ≈ 1300 строк; хуки в `Sidebar`, `CommandPalette`, `Markdown`, `TopicScreen`, `App`, `store` (событие `emit`).
- Каталог доказывает отсутствие ценности: «Помодоро» (= Фокус), «Конфетти» (= награды ради награды), «Шпаргалка формул» (= список формул), «Счётчик слов», «ИИ-вопросы» (= будущая функция ядра).
- Безопасность: JS-код с доступом ко всему, включая сеть; безопасный режим включён по умолчанию, значит, функция почти никем не используется **[оценка]**.
- «Стили»: из 9 пресетов три пересекаются со встроенными настройками («Тетрадь» ≈ фон-клетка + шрифт, «Крупные кнопки» ≈ плотность, «Печатная машинка» ≈ шрифт), остальные — украшения («Свечение», «Стикеры», «Пастельные оценки»). Полезны две идеи — вынести как честные переключатели: **«Спокойный режим»** (скрыть серию/счётчики/советы) и **«Крупные элементы»** (для сенсорного).
- Совместимость данных: поля `modsOn`, `customMods`, `userCss`, `plugins`, `pluginData` оставить в типе, не читать; не стирать у пользователя молча (мягкие миграции, как в CLAUDE.md).

### 5.5 Формулы и рукописный ввод — **рендер формул оставить; «от руки» спрятать/удалить; справку «Формулы» — на сайт**
- В брифе «формулы УБРАТЬ из приложения» — я понимаю как **справку «Формулы»** (шпаргалка LaTeX, `Help.tsx` + `formulaExamples.ts`). Рендер формул в конспектах/карточках (`$…$`, KaTeX), визуальный редактор (MathLive) — ядро для физики/математики/химии. **[Уточнить у автора, если имелось в виду другое.]**

### 5.6 Синхронизация/облако — **ПОЛЕЗНАЯ, но два пути — много**
- Реальный сценарий: писать конспекты на ПК, повторять на телефоне. Без синхронизации это два разных приложения. Значит, синхронизация — почти ядро для тех, у кого оба устройства **[предположение]**.

- Вердикт: один экран «Синхронизация» с простым основным путём (Wi-Fi) и «Для продвинутых: облако». Не расширять.
- Риск: **не проверено на реальных устройствах** (PROJECT.md §12).

### 5.7 Виджеты Android — **оставить 2 из 4**
- Это лучший «безгеймификационный» крючок на телефоне: число карточек и ближайшая домашка видны без открытия приложения.

- **Не проверено на устройстве** (в списке «не проверено» с 1.6). Любое расширение виджетов — только после проверки.

### 5.8 Тема/Оформление — **чрезмерно**
- Фактически: **15 тем** (8 светлых + 7 тёмных, `themes.ts:21-39`; «17» в брифе — это 17 вариантов *значка* телефона: `default` + `theme` + 15), 2 «стиля», 5 шрифтов (+ отдельный выбор шрифта заголовков), 3 «угла», 3 плотности, 4 фона (+картинка), редактор цветов (10 переменных × 2 режима), значок 17 вариантов, анимации 4 уровня × 6 видов.
- Учебная польза у настроек вида только одна — **доступность**: светлая/тёмная, размер текста, контраст, уменьшение движения. Всё остальное — персонализация.
- Предложение (без потери того, что нравится автору): основной раздел «Вид» из 5–6 пунктов: Светлая/Тёмная/Система, цвет (8 вариантов), размер текста, «высокий контраст», «меньше анимации». Остальное (шрифты, углы, плотность, фоны, значок, палитра) — «Ещё» внутри этого же раздела. Тем оставить 6–8. Удалить стиль «Классический» как отдельную систему или превратить в одну тему «Бумага + заголовки с засечками».
- Основная выгода — не размер, а **матрица проверки**: стиль × темы × плотность × углы × шрифты × 3 ширины. Каждая новая функция из брифа (план, подготовка, «+») должна пройти её.

### Что объединить (конкретно)

**A. Планировщик (1 + 9 + 2 + «Подготовиться к завтра» + «Разминка» + «Важные темы» + «Фокус»)** — один механизм `plan(now, minutes)`, возвращающий *блоки*: «к повторению сегодня», «новое», «слабые места», «к контрольной», «завтрашние уроки», «домашка», «стих». **B. «Сделать набор»** — одна кнопка вместо трёх входов + выделение для точечных. Предпросмотр с галочками уже есть (`BulkCards`). Добавить: вставку текста без конспекта, раскладку по спискам (термины/даты/формулы), «Дополнить с помощью нейросети» как опцию.

**C. «Слабые места»** (`weakness.ts` — чистый модуль с тестами): оценка элемента/темы из того, что **уже есть** в данных — вероятность вспомнить сейчас/на дату (`recallAfter`, `srs.ts:539`, стабильность), `lapses`, `difficulty`, давность, число ответов, ошибки с уверенностью (`confidence`). «Тип ошибок» не хранится; для него нужен необязательный выбор причины после «Снова» (+1 касание — только в режиме «разбор»), а не на каждой карточке. Определение, понятное ребёнку: **«Шанс вспомнить на контрольной: 43%»** (в `planFor` уже считается `recallAfter` на день контрольной, `srs.ts:~620`). Показатель в брифе «43%, требуется повторение» естественно выразить так же.

**D. «Разбор ошибок»** — в конце сессии: список «Снова» за сессию + `why` + фрагмент конспекта + «Объяснить проще» (если ИИ) + «Повторить ещё раз» (cram). Сюда же — трудные карточки (leech) и «Ошибки дня» из бэклога. Одна механика вместо четырёх.

**E. «Проверка»** — пробная контрольная, претест и новые типы заданий как **один режим теста** с набором типов вопросов. Ответы теста **писать в журнал** (иначе слабые места не узнают о результатах).

**F. Единый источник «науки»:** один модуль методов (название, что делать, доказательность, ссылка) → онбординг, «Как учиться», совет дня, «Почему?».

**G. Настройки: «Возможности» + «Напоминания» + «Учёба»** — убрать четыре места включения одного и того же; «Возможности» — только один вход.

### Порядок работ — поправка к предварительному порядку автора
Автор: 1 баги → 2 производительность → 3 архитектура → 4 главный UX → **5 автопилот → 6 план → 7 контрольные → 8 слабые места**.
Предложение: **вычесть до сложения** и поменять зависимости:
1. баги/производительность (как есть);
2. **вычитание** (сад, достижения-экран, моды+стили, справка «Формулы/Моды», 2 виджета, 3 входа «карточки из конспекта») — до IA, чтобы не проектировать навигацию под то, что уйдёт;
3. информационная архитектура + главный экран;
4. **слабые места (бывший 8) → контрольная-сущность (7) → планировщик 5+6 вместе** (метрика и сущность — входы автопилота, а не наоборот);
5. «набор из конспекта» (9) → «разбор ошибок» (11) → типы заданий (10, только 2 типа);
6. глобальный «+» (13) — после «набор»: он вызывает те же диалоги;
7. история/корзина (14), «Как учиться» (16), стихи (17), граф (15) — по остатку.

## 7. ОГЭ / ЕГЭ / студенты — реальная позиция

- **Для обычного школьника** — основная ценность (контрольные, домашка, стихи, слова).
- **ОГЭ/ЕГЭ:** подходит «запоминающая» часть подготовки (термины, даты, определения, формулы, орфограммы, слова); не покрывает решение вариантов, сочинения, устную часть. По предметам-«запоминалкам» (история, обществознание, биология, химия-теория, английский) польза высокая; математика/физика — через `problems.ts`. Это **[оценка]**, не измерение.
- Что нужно ОГЭ/ЕГЭ от продукта: длинный горизонт (недели–месяцы), несколько тем в одной «экзаменной» сущности, обзор покрытия («охвачено 60% тем»). Всё это **то же самое**, что нужно для школьной контрольной: **сущность `Exam`** с датой и набором тем. Отдельные режимы «ОГЭ/ЕГЭ» — не нужны.
- **Готового контента нет и быть не должно** (кодификаторы меняются ежегодно, авторские права): максимум — импорт списка тем («структура предмета»), которое можно получить через «файл изменений».
- **Студенты:** приложение работает, но у студентов другие объёмы, PDF/слайды, шаблоны — и для них есть Anki. Не расширять аудиторию искусственно (принцип автора). Ничего специально не делать; не писать в описании.
- Честная позиция: **«для школьника 5–11 классов, который хочет не зубрить перед контрольной»**.

## 8. Чего по-настоящему не хватает

1. **Бюджет времени и разгребание долга.** Нет «у меня 10 минут» и нет «болел неделю — как разгрести без стресса» (сейчас: 144 карточки, «1 из 144»). Тут же в `tips.ts` уже есть совет при >150 повторений — но это текст, а нужна кнопка. Ценность 5, сложность 2–3.
2. **Результат контрольной.** Поле «какую оценку получил» после даты контрольной; сравнение с прогнозом готовности; график «готовность → оценка». Единственная честная проверка девиза продукта и лучший аргумент для ученика, что метод работает. Ценность 4, сложность 2 (нужна сущность `Exam`).
3. **Вставить текст → набор без ИИ.** Автовыделение (даты, определения «X — это», жирное) работает и на обычном тексте. Закрывает холодный старт, когда текст уже в электронном виде (электронный учебник, РЭШ, чат с учителем, ответ нейросети) и фото не нужно; OCR с фото на телефоне пока не проверен. Ценность 4, сложность 2.
4. **Картинка с закрытыми частями** (география, биология, физические схемы). Стандарт в Anki, в школьных предметах постоянная потребность; в Мнеме нет (в бэклоге помечено). Ценность 3–4, сложность 3–4.
5. **«Путаю эти два»** — карточка-различение (бэклог 1.6.3). Ценность 3, сложность 2.
6. **«Когда тебе удобно учиться?»** при первом запуске (утро / после школы / вечер) → время напоминания. Эффект «если–то» планов хорошо описан; сложность 1, ценность 3.
7. **Единое управление «шумом»:** переключатель «Спокойный режим» (без серии, счётчиков, советов). Сейчас только CSS-мод.
8. **Расписание повторений для тем с малым количеством карточек** (3–5 карточек в теме не образуют «растения», «готовности» и «плана»): показывать готовность только при ≥ N карточек.
9. **Измерения для самого автора:** локальный экран «как пользуются» (счётчики включённых функций; без отправки) — чтобы решения «убрать/оставить» опирались на данные. Сейчас всё — догадки.

## 9. Научная опора — что можно утверждать, что нет

Из обзора Dunlosky и др. (2013, PSPI; проверил краткое изложение): **высокая** полезность — практическое тестирование (самопроверка) и распределённое повторение; **умеренная** — «почему?» (elaborative interrogation), самообъяснение, перемешивание; **низкая** — перечитывание, выделение маркером, конспектирование-резюмирование. Эти формулировки в `tips.ts` соответствуют.

Для «Как учиться»: безопасно подавать как доказанные только два высоких приёма; остальные — «помогает, но доказательств меньше». «Стили обучения», «лучше пишешь рукой» — не подавать как факты.

Для стихов (по памяти и по литературе, **не перепроверял по первоисточникам в этой сессии**, кроме п. ниже):
- активное вспоминание и повторение с интервалами — сильная база (то же, что для карточек);
- «проговаривание вслух» (эффект произнесения) — устойчивый, но небольшой эффект в лабораторных заданиях;
- **целиком против по частям:** классические исследования говорят неоднозначно — для взрослых «целиком» лучше до ~240 строк, дети до 12 лет чаще лучше учат по частям, кроме материала с цельным смыслом; метод по частям лучше для немедленного, целиком — для долгого запоминания (краткая сводка по поиску; источник старый, не современный обзор) → «нарастающие части» в Мнеме **обоснованы условно, не как доказанный лучший способ** — формулировки в приложении смягчить;
- «исчезающие подсказки / первые буквы» — метод известен из реабилитации памяти; для здоровых школьников доказательная база скромнее. Пока это **разумная практика, не доказанный факт**;
- интервалы 1/3/7×2.4 дней — эвристика, а не FSRS; допустимо, но не «научно оптимальный»;
- сон — закрепляет заученное: поддержано, но «учи вечером, повтори утром» — совет, не точное правило.

## 2. Скрытые противоречия внутри самого списка автора

1. **«Не копить функции» vs 16 новых пунктов.** Список в основном добавляет, а не заменяет.
2. **«Выключенная функция нигде не видна» + «новое — за переключателем» vs умный план/автопилот, которые «анализируют всё».** План читает расписание, домашку, контрольные, стихи, ИИ. Каждая комбинация вкл/выкл — отдельный режим теста: 21 переключатель уже (`featureList.ts:26-48`), плюс «план», «набор», «ИИ в конспекте», «история»… Матрица состояний взрывается. План должен деградировать молча, а это надо тестировать.
3. **«Одна главная кнопка» vs «Начать план» + «Учиться» + «Исправить»** — три главные кнопки в трёх пунктах списка. А на «Сегодня» их уже: «Начать», «Фокус N минут», «Готовиться · N» (на каждую контрольную), «Учить · N» (на каждую важную тему), «Подготовиться к завтра · N», «Разминка · 5» [код: `Today.tsx:115,119,177,216,331,336`]. Это уже и есть болезнь, которую лечит автопилот; добавление «Начать план» её ухудшит.
4. **«Обучение важнее геймификации» vs Сад (гладить растение, сердечки) и серии-значки** — автор сам же просит их проверить (баги 5, 6), это согласуется; но пункт **«Учусь»** с «планом выполнен на 70%» легко превращается в ту же механику. Следить.
5. **«Не расширять аудиторию» vs пункт ОГЭ/ЕГЭ/студенты.** Сам пункт — расширение аудитории.
6. **«Перенести документацию на сайт» vs «Офлайн-приложение для школьников»** (`CLAUDE.md`, `docs/PROJECT.md:9`). Сайта нет (в `docs/` только `PROJECT.md` и `formulas.md`). Ребёнок на телефоне без интернета в школе справку не откроет. Правило «в приложении только необходимая помощь» верно, но «необходимое» обязано быть внутри.
7. **«Простота ≠ мало функций»** — верно, но тогда критерий «сколько нажатий до результата», а не «сколько функций». Ни один пункт списка не сформулирован через «минут до результата».
8. **«Учусь → Знания → Профиль» кладёт «Статистику» в «Знания»**, а статистика — про меня, а не про знания.

### Баг 2. «Квадратик» инструментов появляется слишком рано

1. Дубля нет.
2. —
3. Если «чинить» вторым механизмом (таймер, высота шапки) — получим хрупкость на разных экранах.

### Умный план / автопилот / подготовка к контрольной — это один механизм

1. **Да, это три имени одного механизма: «собрать из доступных источников упорядоченный список заданий на сегодня».** Источники: просроченные повторения, новые карточки, контрольные (уже в `buildQueue` через `examBoost`), предметы завтрашних уроков (уже), стихи на сегодня (отдельная строка в `Today.tsx:147-156`), домашка (`Today.tsx:145`), слабые места. Порядок = приоритет. «Автопилот» = кнопка, запускающая его. «Умный план» = его показ списком. «Подготовка к контрольной» = источник с приоритетом и датой. Три экрана и три кнопки = три места, которые будут расходиться.
2. **Время.** Ребёнок: 15 минут, телефон, на перемене. Автопилот «10 мин слабая тема + 5 мин карточки…» ломается об SRS: просроченные повторения нельзя «обрезать по времени» без накопления долга. Уже есть `maxReviews: 200` (`store.ts:140`), `tips.ts` про «долг» (`tips.ts:75-83`). Время-бюджет должен жить как **срез сверху** очереди по приоритету («Минимум на сегодня: 5 мин» = `limit`), а не как заранее нарезанные блоки по темам.
3. **Опасно:**
   - Домашка — свободный текст («упр. 5, стр. 34», `types.ts:34-46`): приложение не может её «запустить» и не может проверить. Шаг «сделай домашку» = чек-лист (to-do), а автор прямо говорит «это не To-Do». Домашку в план не как шаг, а как строка-напоминание.
   - Экран «идёт по шагам» требует оболочки над четырьмя разными экранами (`Review`, `TestScreen`, `PoemView`, домашка) с состоянием между ними. Состояние плана хранить **нельзя** в `AppData` (раздувание + синхронизация) — оно должно быть чистой функцией `plan(data, now)`; прогресс = то, что уже есть в `logs` за сегодня.
   - Пересчёт плана после каждого шага меняет порядок «под ногами» (как сейчас с `buildQueue`, но заметнее на экране-списке).
4. **Не замечено:** сегодня **на «Сегодня» шесть разных запускателей** (см. §2.3). Первая задача — слить их, а не добавить седьмой. И очередь `buildQueue` уже «автопилот» для карточек.
5. **Объединить:** один чистый модуль `session.ts` → `buildSession(data, now, {minutes?}) → шаги[]` (тесты, как у `srs.ts`), одна кнопка **«Начать»** (имя оставить — оно в приветствии и справке) с подписью «≈12 мин · 3 шага», раскрывающийся список шагов под ней, «Минимум на сегодня · 5 мин» в «⋯». Экран «Контрольные» остаётся как источник, без отдельной кнопки-запускателя (строка контрольной = ссылка на шаг/экран темы).
6. **ОБЪЕДИНИТЬ три пункта в один.** «Начать план» как вторая кнопка — **УБРАТЬ**.

4. **Цена по синхронизации [код]:** `mergeData` берёт «более новую» версию темы целиком (`sync.ts:12-15,35-52`).

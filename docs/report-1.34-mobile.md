# Телефон и понятность: отчёт

Ветка `claude/relaxed-maxwell-tz94am` в Mnema и Mnema-site. Скриншоты «до/после» — `docs/screenshots/`,
вывод тестов на старом коде — `docs/test-evidence/`.

## Стек (разведка)

- Приложение: TypeScript + React 19 + Vite, редактор конспекта — TipTap (ProseMirror), хранение — Markdown.
- Windows и Linux — Electron (`electron/`); Android — своя обёртка WebView без Capacitor (`android/`, targetSdk 34,
  `adjustResize`); веб-версия (PWA) — та же сборка с мостом `src/platform/web.ts`, выкладывается в `Mnema-site/app/`
  workflow-ом `web.yml` из `main`.
- Сайт — статический HTML/CSS/JS, отдельный интерфейс для телефона (`css/mobile.css`, `js/mobile.js`).
- До работы: `tsc` чисто, 90 файлов / 1303 модульных теста проходили; линтера в проекте нет; e2e — отдельные скрипты
  `e2e/*.mjs` без раннера и без CI.

## 1.1. Номер страницы

Списков с постраничной листалкой в приложении нет (длинные списки — «Ещё N», `Capped`). «N из M» с кнопками —
только в просмотре фото страниц учебника (`PageViewer`). Там номер был текстом. Теперь — общий `Pager`
(`src/components/Pager.tsx`, логика `src/pageNumber.ts`): поле `inputmode=numeric`, `enterkeyhint=go`, Enter/уход из
поля — переход, Esc — отмена; целое ограничивается диапазоном, пусто/дробь/буквы — прежняя страница; принимается
настоящий номер страницы учебника (45, 46, 48…), нет такого — ближайшая. Поле 44×44, при клавиатуре прокручивается
на виду.

## 1.2. Меню «⋮»

Причина наложения: `.menu` — колонка flex, у пунктов явный `min-height: 40px`. Когда меню не помещалось и `fitInView`
ограничивал его высоту, пункты сжимались до 40 px (явный min-height отменяет «не меньше содержимого»), а вторая
строка-пояснение вылезала на соседний пункт. Плюс меню ограничивалось только по ширине `.main`, а по высоте — окном,
поэтому уходило под нижнюю панель; 🐞 (z-index 64) лежал выше меню (40).

Сделано: пункты не сжимаются, текст переносится; на телефоне `MoreMenu` — шторка в `<body>` (z 75) с затемнением,
ручкой, свайпом вниз, тапом мимо, Esc и системной «Назад»; на компьютере меню не выходит за `.main`; 🐞 и таймер
прячутся при открытом меню/окне. Меню предмета и темы сгруппированы (Учить · Подготовка · Управление · Экспорт, у темы
ещё «Карточки»), «Удалить» — внизу за чертой, подсказки короче, «15 карточек на сегодня» видно до нажатия.
Исправление в CSS действует на все `.menu` приложения; все меню ключевых экранов проверяются тестом `menus-all`.

## 1.3. Системные панели и клавиатура

- `viewport-fit=cover` и `interactive-widget=resizes-content` уже были; Chrome на Android 15+ при этом рисует страницу
  под жестовой полосой. Отступы теперь — переменные `--safe-*` (большее из `env()` и `--native-*`), их получают всё
  приложение (вырез сбоку, полоса снизу без нижней панели — повторение и тест), тосты, тур, боковая панель, редактор
  стилей, полноэкранный конспект, «Важное».
- Android: обёртка передаёт `--native-*` — пересечение окна с системными панелями (а не сырые отступы, чтобы не было
  двойного отступа при targetSdk 34).
- Клавиатура распознаётся и когда окно не меняется (Safari), и когда уменьшается (WebView `adjustResize`); приложение
  сжимается до видимой части, поле в фокусе прокручивается на виду.
- «Вставить» одним нажатием в полях импорта (карточки, термины списком, стих, источник, файл изменений) — мост
  `clipText` на Android, `navigator.clipboard` в браузере; поля на пальце — шрифт ≥ 16 px.

## 1.4. Конспект на телефоне

Панель над клавиатурой (отменить/вернуть, заголовок, список, Ж, К, маркер, «В карточку», «Готово»), «Сохраняется… /
Сохранено / Нет сети — сохранено на устройстве», режим «Читать / Править», для пустого конспекта — шаблоны «По теме»
и «По главе», «Вставить из буфера», «Из учебника»; в «Создать» первым — «Новый конспект». Сохранение — через 300 мс и
сразу при сворачивании/уходе/закрытии, поэтому вопрос «сохранить?» не нужен. Длинный конспект (3000 абзацев) и ввод
через IME проверены тестами.

## Масштаб

«Настройки → Оформление → Масштаб» 75–150 %, только на этом устройстве. Electron — `webFrame.setZoomFactor`,
Ctrl + / − / 0 и Ctrl+колесо через приложение; телефон — ширина в meta viewport (в WebView включены wide viewport и
масштаб двумя пальцами); браузер на компьютере — подсказка про масштаб браузера.

## Понятность

Подсказки при первом открытии экранов, «Помощь»: поиск и «Словарь», `docs/glossary.md`; у темы «3 сегодня» и
«выучено 40%»; «▶ 15» подписана; хлебные крошки с папкой; «Назад» по уровням и выход вторым нажатием; копия —
с «Открыть» и «Отменить»; контраст WCAG AA; двойное касание «Создать» больше не создаёт дубликат.

## Что не проверено и риски

- Нет реального телефона: Android WebView, Safari на iPhone, вырезы, жестовая и трёхкнопочная навигация, системный
  размер шрифта и настоящая клавиатура проверены эмуляцией в Chromium (подмена отступов и `visualViewport`).
- APK не собирался: в окружении нет Android SDK (доступ к dl.google.com закрыт). Java-код (`AppActivity`: отступы,
  wide viewport и масштаб двумя пальцами; `Bridge.clipText`) проверен только на синтаксис; использованные API —
  уровня 21–23 при minSdk 24. Перед выпуском нужна сборка и проверка на устройстве.
- Electron-часть масштаба (`before-input-event`, `webFrame.setZoomFactor`) не запускалась (нет дисплея).
- Скриншотные эталоны сняты в этом Chromium; на другой машине эмодзи могут отрисоваться иначе (порог 2 %).
- Папка `Mnema-site/app/` не пересобиралась: её обновляет `web.yml` после слияния в `main`.
- Плашка «1.29 Новое…» на мобильной главной сайта устарела — это часть выпуска, не трогал.
